### Почему `model_precision` 71–72%, а не 90%

Разбор ошибок dev (`data/cache/eval/s6_errors.py`): из 477 строк в модельных группах неверны
133. У 101 из них эталон — описание (`DESCRIPTOR`), у 8 — `NONE`, у 24 — другая модель. 111 из
120 ошибочных линеек дают по одной ошибке: это длинный хвост однословных найденных линеек
(Wheat, Crew, Crest, Script, Rainbow, Handle, Two Tone, 90s…), а не несколько крупных
линеек. Ни правило линейки, ни дубли, ни подтверждение моделей (шаги 4–6) их не трогают.
Следующий рычаг — не одна правка, а отдельная работа: порог поддержки для однословных
линеек, расширение словаря описаний по хвосту или подтверждение через `--candidates` глубже
топ-50. Словарь в лоб рискованно расширять дальше: он начнёт резать настоящие модели.

2. **Подтверждение моделей.** По плану отмечает заказчик. В этой сессии отметил Claude
   (решение 7): из топ-50 кандидатов перенесены в `config/models/balenciaga.yaml` только

3. **Ленивые `types: any`** (`seeds.py`): seed получает группу в типе, только если его

## Решение заказчика по `model_precision` (2026-10-09)

Оставить как есть, логику не менять. Популярные вещи распознаются чисто (топ-50 — 0% мусора,
топ-100 — 6% мусора и дублей), ошибки сидят в хвосте линеек на 1–2 продажи. Порог «однословная
найденная линейка с < N продаж — не модель» на dev поднял бы точность до 88% (N = 10) или 90%
(N = 20), но скрывал бы новые модели, пока они не наберут N продаж, — для «Трендов» это хуже.
Расчёт: `data/cache/eval/s7_threshold.py`.
