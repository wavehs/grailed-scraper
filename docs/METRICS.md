# Метрики и тренды (metrics-v2)

Цель — находить самые ликвидные дорогие вещи для перепродажи: их часто покупают, они
быстро уходят, их лайкают, и стоят они дорого. Рейтинг строится только на этих четырёх
показателях; рост продаж, sell-through и «новинки» в рейтинг не входят (в v1 рост
выводил наверх выборки из 3–5 продаж: «5 против 0» = рост ×6).

## 1. Таблица `group_metrics`

Одна строка на область, без снимков по запускам: экран всегда показывает все бренды по
всем собранным данным, а не только последний запуск.

| `scope` | `scope_key` | Что входит |
|---|---|---|
| `model` | `model:<group id>` | линейка — вместе со своими версиями; версия — только свои объявления |
| `type` | `type:<brand id>:<type>` | все объявления бренда этого типа |
| `brand` | `brand:<brand id>` | все объявления бренда, кроме «Требует проверки» |

Пересчитывается одним проходом по объявлениям бренда (`services/metrics/`) после каждого
сбора, после перегруппировки и после ручной правки группы, а вручную —
`python -m app.cli metrics`. 440 тыс. объявлений — около 12 секунд вместе с рейтингом.

Исключения: `possible_replica` не учитывается вовсе; `price_outlier` и `lot_or_bundle`
не входят в медианы цен. Все суммы — `Decimal`, в API — центы.

## 2. Показатели

Все окна заканчиваются моментом расчёта `as_of`.

| Поле | Формула |
|---|---|
| `sold_7d`, `sold_30d`, `sold_90d` | продажи с `sold_at` в окне |
| `sold_prev_30d` | продажи за 31–60 дней назад |
| `weekly_sales`, `weekly_median_price` | 12 недель, от старой к новой |
| `median_days_to_sell` | медиана `sold_at − created_at` по точным продажам за 30 дней; для перевыставления — от первого объявления (`relist_of_id`) |
| `median_price_{7,30,90}d` | медиана `sold_price ?? price` |
| `windows` | для каждого периода 7, 14, 30, 60, 90, 180, 365 дней: `sold` — продажи, `price` — медиана цены, `days` — медиана дней до продажи (точные продажи), `likes` — медиана `likes_count` проданных объявлений (лайки активных не считаются: это ещё не спрос, превратившийся в продажу); периоды без продаж не хранятся |
| `period_sold`, `period_median_price`, `period_median_days`, `period_median_likes` | период рейтинга, скопированный из `windows` при ранжировании, — для сортировки и фильтров списка |
| `liquidity_score` | рейтинг 0–100, раздел 3; пусто — ниже порога |
| `price_change` | `(median_30 − median_90) / median_90` |
| `active_now` | активные объявления сейчас |
| `new_listings_14d` | новые объявления за 14 дней (без перевыставлений) |
| `sell_through_30d` | `sold_30d / (sold_30d + active_now)` |
| `first_seen_at`, `is_new` | самое раннее объявление области; новинка — моложе 60 дней |
| `colors`, `sizes` | продажи за 90 дней и активные по каждому цвету/размеру, sell-through |

`sold_prev_30d`, `price_change`, `new_listings_14d`, `sell_through_30d`, `growth`, `speed`
и `is_new` по-прежнему считаются и хранятся, но не входят в рейтинг и не отдаются в
списке трендов.

## 3. Рейтинг ликвидности (настраивается на экране трендов)

Все параметры меняются в интерфейсе: переключатель периода и панель «Настройки рейтинга»
на экране трендов (`/api/settings/liquidity`). Сохранённая политика лежит в
`app_settings.liquidity_policy`; `config/liquidity.yaml` — значения по умолчанию, к ним
возвращает «Сбросить по умолчанию».

**Период.** 7, 14, 30 (по умолчанию), 60, 90, 180 или 365 дней. Все четыре показателя
берутся за один и тот же период из `windows`.

**Порог.** Рейтинг получает только строка, у которой одновременно:

- продажи за период, пересчитанные на месяц (`sold × 30 / период`), не меньше
  `min_sales_per_month` (по умолчанию 5) — меньше продаж это шум;
- медианная цена за период не меньше `min_price_usd` (по умолчанию $150);
- известна медиана дней до продажи за период;
- раздел не из `excluded_sections` (по умолчанию `dresses`, `other`).

**Оценка.** Для каждого из четырёх показателей считается перцентиль внутри всех строк
того же уровня, прошедших порог (по всем брендам сразу): худшие значения считаются
целиком, равные — наполовину. Затем (веса по умолчанию)

```
liquidity = 100 × (0.40 × P(продажи) + 0.25 × P(−дни до продажи)
                   + 0.20 × P(лайки) + 0.15 × P(цена))
```

Веса задаются любыми неотрицательными числами (например, процентами 50/30/20/0) и
приводятся к сумме 1; хотя бы один должен быть больше нуля.

Уровни ранжируются отдельно: линейки моделей (без «Без модели», описаний, retired-групп и
«Требует проверки»), типы товаров, бренды. Версии моделей рейтинга не получают.
Перцентиль зависит от состава пула: новый бренд немного сдвигает оценки остальных, сами
показатели при этом видны рядом с оценкой.

**Когда пересчитывается.** Метрики всех периодов считаются после сбора, перегруппировки и
`python -m app.cli metrics` (~26 с на 444 тыс. объявлений). Смена настроек только
переранжирует уже посчитанные `windows` (~0,4 с), поэтому применяется сразу. Если
сохранённая политика перестала проходить проверку (например, из таксономии убрали
раздел), в лог пишется `liquidity_policy_invalid` и используются значения по умолчанию.

После миграции `20261016_0021` рейтинг пуст, и список трендов пустой до первого
пересчёта: сбора, перегруппировки или `python -m app.cli metrics`. Сбор нескольких
брендов ранжирует таблицу один раз после всех брендов.

Пример: из трёх моделей лучшая по всем четырём показателям получает `100 × 5/6 = 83.33`,
средняя по всему, кроме худших лайков, — `43.33`. На данных 2026-10-16 с настройками по
умолчанию порог проходят 89 из ~15 000 линеек; первые — MM Future, RO Geobasket,
RO Detroit, RO Ramones, Balenciaga Strike. За 365 дней первые — RO Geobasket, MM Future,
MM Paint Splatter, RO Ramones, MM GAT.

## 4. API

- `GET /api/trends` — `level=model|type|brand`, фильтры `brand_ids`, `section`,
  `product_type`, `price_min`/`price_max` (USD, по медиане за период рейтинга),
  `min_sales` (продажи за период), `search`; сортировка `sort=liquidity|sales|speed|likes|price`
  (по умолчанию `liquidity`; `speed` при `desc=true` — самые быстрые сверху).
  По умолчанию отдаются только строки с рейтингом; `include_unranked=true` добавляет
  строки ниже порога (в конце списка); группы «Без модели» и описания, запрошенные через
  `include_fallback`/`include_descriptors`, показываются и без него. В ответе `ranking` —
  период, порог и веса; в строках — `period_sold`, `sales_per_month`,
  `period_median_days`, `period_median_likes`, `period_median_price`.
  На уровне `model` показываются линейки без групп «Без модели».
- `GET /api/settings/liquidity` — текущие настройки рейтинга, значения по умолчанию,
  допустимые периоды, `saved` (сохранены ли свои). `PUT` — сохранить и сразу
  переранжировать (в ответе `ranked` — сколько строк получили оценку; ошибка проверки —
  422 `invalid_liquidity_policy`). `DELETE` — сбросить к значениям по умолчанию.
- `GET /api/trends/groups/{id}` — карточка: метрики, недельные ряды, версии, цвета и
  размеры, последние продажи и активные объявления со ссылками на Grailed.
- `GET /api/listings?product_type=` — каталог с фильтром по типу.
