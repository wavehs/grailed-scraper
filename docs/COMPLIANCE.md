## 18. Этика, право, ограничения

- Собираются **только публично доступные** данные листингов; поисковый ключ Algolia — search-only, публично отдаётся фронтендом самого Grailed.
- Никаких write-операций Algolia, никакой авторизации в чужие аккаунты, никаких браузеров и **никакого обхода капчи**; если источник отвечает CAPTCHA/WAF или явно требует не автоматизироваться — прогон останавливается.
- HTML-страницы не парсятся: единственный HTML-запрос — страница конфигурации для получения публичного поискового ключа.
- Вежливые дефолты: ≤ 90 запросов/мин, ≤ 3 параллельных, экспоненциальный backoff, немедленное снижение скорости при 429.
- Данные хранятся локально; персональные данные продавцов не собираются (см. §14.4);
  перепродажа/публикация датасета не предполагается. Это ограничение не отменяет ToS и
  не считается разрешением на автоматизированный доступ.
- В README — явный дисклеймер: пользователь несёт ответственность за соответствие ToS площадки и локальному законодательству.

### Обязательный checklist перед live-доступом

- Проверить актуальные ToS источника, `robots.txt` и применимое законодательство.
- Убедиться, что сценарий ограничен публичными read-only данными; не публиковать и не
  перепродавать набор данных.
- Оставить лимиты не выше 90 запросов/мин и трёх одновременных запросов. Конфигурация
  отклоняет более высокие значения, в том числе загруженные из SQLite Settings.
- Только после проверки задать `APP_LIVE_COMPLIANCE_ACKNOWLEDGED=true`. Флаг читается
  исключительно из окружения и никогда не сохраняется в SQLite.
- Без acknowledgement live discovery, parser run и canary завершаются до создания
  HTTP-клиента и до любого сетевого действия.

### Seller identity и raw data

Режим по умолчанию — `hashed`: `SHA-256(normalized_username + local_salt)`, где соль
берётся из `APP_SELLER_IDENTITY_SALT` либо единожды создаётся в игнорируемом
`data/secrets/`. `none` ничего не сохраняет. Переход в `plain` требует отдельного
неперсистентного подтверждения через Settings и создаёт постоянное health/UI
предупреждение. Числовой seller ID, email и геолокация точнее страны удаляются из
нормализованных данных, raw JSON и примеров schema; соль никогда не попадает в API.
